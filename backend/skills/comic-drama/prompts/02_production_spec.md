# C2 · 生产规格

## 目标

把创意反推成**可执行的生产规格**——让后面的每个阶段都有明确数字可依。

规格不是"设定说明"，它必须能回答：做几格？每格几秒？大概花多少钱？

## 关键计算

```
格数 = 总时长 ÷ 每格时长
```

每格 4~6 秒是竖屏动态漫的舒适区间：
- 低于 4 秒 → 观众来不及看清画面
- 高于 6 秒 → 节奏塌，注意力流失

默认取 5 秒。**把这个算式写进输出**，让用户看到格数是算出来的，不是猜的。

## 节奏表

不要 12 格都一个节奏。按叙事功能分段，每段给不同的平均时长：

| 段 | 功能 | 特点 |
|---|---|---|
| 开场 | 抛钩子 | 最快，前 5 秒定生死 |
| 升级 | 建立冲突 | 稍慢，让台词有重量 |
| 爆发 | 反转 | 由慢转快 |
| 收尾 | 留悬念 | 定格 |

## 最小可信路径

标记 `sample_panels`（前 N 格先做样片）。
默认 3 格：成本几乎为零，但能避免铺完 12 格才发现画风不对。

## 输出

写入 `spec.json`，字段：`grid_count` / `seconds_per_panel` / `total_duration_seconds` /
`tolerance` / `resolution` / `aspect_ratio` / `fps` / `sample_panels` /
`rhythm_table` / `visual_pipeline` / `budget_estimate` / `decisions`。

## 自检

- 格数是不是算出来的？如果不是，重做。
- `budget_estimate` 是否给了**区间**和**假设**？给一个精确到分的假数字是不诚实的。
- 有没有偷偷把"节奏"设计成每格一样长？
