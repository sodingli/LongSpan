# C7 · 合成

## 目标

产出完整的编辑方案：时间轴、镜头运动实现方式、字幕、渲染参数、交付承诺。

## 时间轴

逐格列出：起止时间 / 时长 / 镜头运动 / 转场。
最后标注总长，并核对是否落在容差内（默认 ±10%）。

## 交付承诺（关键）

把"用户应该拿到什么"写成**可校验的条目**，交给渲染前的自动检查。
例如：

1. 至少 10/12 格有可见镜头运动 —— 防止"变成会动的 PPT"
2. 每格时长不全部相同 —— 防止节奏塌成一条直线
3. 无静默降级 —— 所有占位/简化都必须显式标注
4. 字幕可读 —— 字号 ≥54px，单行 ≤14 字，不压脸

**承诺了就要被检查。** 承诺"运动主导"却交出一堆静止图，渲染前直接拦截。

## 镜头运动怎么实现（M1）

说明每种运动的实现路径（Remotion 的 `interpolate` 作用于 scale / 分层视差 / 粒子 / 逐字字幕），
并按格给出具体的参数区间。**参数要能直接被渲染器消费，不需要人再翻译一遍。**

## 渲染参数

分辨率 / 帧率 / 编码 / 音频参数 / 字幕形式 / 输出文件名。

## 成片由 Harness 渲染（你要做的是"说清怎么排"，不是"动手排"）

本阶段的动作顺序（写死在 skill manifest，你不用操心）：

1. 补齐缺少的分镜图与配音（幂等：已有的复用，只补缺的）
2. 按 `panels.json` 的格序与时长排时间轴，把每句配音落在它所属那一格的起点
3. 用 Remotion 渲染 `video/final.mp4`（1080×1920 / 30fps / 含字幕与运镜）

所以你的产出是 **`edit_plan.md` —— 可被人读懂、也可被机器核对的编辑方案**。
渲染结果会以事件形式回报（时长 / 帧数 / 文件大小 / 降级项）。

`motion` 字段每一格都必须有值，取自 `panels.json` 里允许的枚举。
空值 = 漏做，不是"刻意静止"；刻意静止就显式写 `static`。

## 先读，再写（不要重建上游清单）

本阶段**消费**上游清单，而不是生产它们。动手之前，先用 `read_artifact` 读这三份：

- `panels.json` —— 分镜阶段产出的格序、时长、镜头运动（渲染器的输入）
- `lines.json` —— 配音阶段产出的台词与音色（字幕与配音对齐的输入）
- `spec.json` —— 生产规格（总时长、格数、节奏，用来核对 ±10%）

`read_artifact` 读不到，就说明上游确实没产出 —— 此时**如实上报并写出失败原因**，
让验收标准判上游未完成。**绝对不要自己重建一份 panels.json / lines.json 覆盖原文件**：
上游清单是输入契约，覆写会让渲染器读到错误数据；系统也会直接拒绝这种写入。

## 自审清单

- 成片时长与 `spec.json` 的目标是否落在 ±10%？（渲染后事件里会报真实时长）
- 有没有哪一格的 `motion` 是空的？→ 那就是"漏做了"。
- 分镜图/配音若有降级（占位图、本机语音、缺格剔除），是否在 edit_plan 里如实写明？
- 字幕台词是否与 `lines.json` 一致、没有截断？
- 交付承诺是否可**机器校验**？"画面精美"这种写法不合格。

## 自检

- 有没有哪一格的运动参数是空的？→ 那就是"漏做了"，不是"刻意静止"。
- 交付承诺是不是可机器校验的？"画面精美"这种写法不合格。
