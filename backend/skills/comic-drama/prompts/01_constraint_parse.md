# C1 · 约束解析

## 目标

把用户的一句话输入拆成三层，并给出你对这个创意的解读。

**不要向用户提问。** 凡是能从创意本身推出来的，直接定，并记入 `decisions`。
用户看到具体方案后否定，远比从零描述容易。

## 三层怎么分

| 层 | 判据 | 示例 |
|---|---|---|
| 硬约束 | 用户明确写出来的，或物理不可变的 | 题材、时长、集数、画风、平台、核心冲突 |
| 软偏好 | 用户没写，但可从创意合理推知 | 基调、节奏、受众、结局倾向 |
| 自由区 | 剩余的全部——这是你的发挥空间 | 配角、台词措辞、镜头语言、转场、道具 |

**最容易犯的错**：把软偏好当成硬约束，于是自由区被压缩到几乎没有，后面每个阶段都畏手畏脚。
自由区要给得足够大。

## 输出

写入 `constraints.json`：

```json
{
  "interpretation": "一句话说清这个创意的戏剧核心是什么（不是复述，是判断）",
  "hard_constraints": { "题材": "...", "核心冲突": "..." },
  "soft_preferences": { "基调": "...", "节奏": "..." },
  "free_zone": ["...", "..."],
  "decisions": [
    {"what": "...", "why": "...", "alternatives": [{"option": "...", "confidence": 0.7, "reason": "..."}]}
  ]
}
```

## 自检

- `interpretation` 是在**判断**（"戏剧核心是身份错位的当众揭穿"），还是在**复述**（"讲一个外卖员被主厨约战的故事"）？后者不合格。
- 自由区是否有 ≥4 项？少于 4 项说明你把太多东西当成了硬约束。
