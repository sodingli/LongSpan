# 视频质量第二轮审阅报告（换脸根因深度定位）

> 日期：2026-10-23 ｜ 对象：comic-drama 图生视频全链路 ｜ 方法：独立 DB 隔离跑通真实 slow 通道 + 逐格抽帧/数据比对

---

## 一、结论先行

这次我把流水线用**独立 DB 隔离**跑通了（规避了上轮的环境并发干扰），并在真实生图阶段把「换脸」这个历史顽疾**用机器抽检精确量化**了：**12 格里有 10 格同人评分 ≤1.0（满分 5），换脸率 83%。**

换脸不是单一原因，而是**三层叠加**，从上游到下游依次是：

| 层 | 根因 | 是否可修 | 优先级 |
|----|------|---------|--------|
| **① 分镜 prompt 锚点标签丢失** | 模型在部分格没写 `XXX_ANCHOR` 标签，直接重新描述角色 | 框架可修 | P0 |
| **② 参考图定位误判** | 无标签时，`_find_reference_art` 的「内容匹配」把角色 A 误判成角色 B | 框架可修 | P0 |
| **③ 参考图通道遵循度不足** | 即使参考图正确带上，`qwen-image-3.0-pro` 对动漫跨景别一致性遵循度仍不足 | 能力层，需评估 | P1 |

下面逐层给证据。

---

## 二、三层根因的证据链

### ① 分镜 prompt 锚点标签丢失（模型层面）

`panels.json` 里格 1 / 格 4 / 格 8 的 `prompt` **没有任何 `XXX_ANCHOR` 标签**，模型直接重新描述了角色：

```
格1 action=陆子昂站在评审台前  → prompt 开头是「2D anime cel-shaded...」（无 LUZIANG_ANCHOR）
格4 action=阿杰在出租屋打字      → prompt 无 AJIE_ANCHOR
格8 action=阿杰的手拿出小铁盒    → prompt 无 AJIE_ANCHOR
```

框架的「分镜一致性校验」硬闸**正确抓到了**这一点（连续打回 2 次：「格4/格8 未复用任何角色锚点」），但模型每次只修一个格、又漏另一个，导致返工循环、最终耗尽 40 分钟墙钟。**这证明约束层在起作用，但「锚点复用」这件事对模型的稳定性依赖过重。**

### ② 参考图定位误判（框架 bug，本轮最确凿的发现）

`_find_reference_art` 的三级查找在「无标签」时会走**内容匹配**（用锚点原文与 characters.md 做逐子句相似度）。实测抓到一次**跨角色误判**：

- **格 1 实际是陆子昂**（白金厨师服，panel-01 画面正确）
- 但 `_find_reference_art` 给它匹配到了 **`anchor_3` = 小杨**（橙马甲蓝头盔）

原因：格 1 的 prompt 无 `LUZIANG_ANCHOR` 标签，内容匹配时，小杨锚点里的「马甲 / 头盔 / 蓝」等通用词碰巧在格 1 的 prompt 里命中 ≥2 个子句，被误判为小杨。**参考图传错人 → 抽检拿「小杨」去比「陆子昂」，当然判 1.0 分。**

这是「框架与约束没做扎实」的典型：**内容匹配在没有标签时不可靠，但框架没有对「匹配结果的置信度」做兜底校验。**

### ③ 参考图通道遵循度不足（能力层）

最值得警惕的是：**即使参考图正确带上的 6 格（走 qwen-image-3.0-pro），同人评分依然只有 1.0。**

这说明 `subject_reference` 通道对「动漫人物跨景别一致性」的遵循度不足——参考图（正面半身定妆图）与分镜（wide/close/不同角度）差异过大，模型没有真正「照着参考图画人」。

---

## 三、provider 混用的另一个问题

真实数据里 12 格出现了**两个 provider 混用**：

```
dashscope/wan2.2-t2i-plus        5 格   ← 不支持参考图
dashscope-mm/qwen-image-3.0-pro  7 格   ← 支持参考图
```

`.env` 已配 `LONGSPAN_IMAGE_PROVIDER=dashscope-mm`，但 `image_routing=auto` 在「无参考图」的格走了原始通道顺序命中 wan22。**同一条流水线里混用两个能力不对称的通道，是「约束不扎实」的又一表现**——应该让「参考图能力」成为硬约束，而不是 auto 路由的软偏好。

---

## 四、本轮已落地的修复（图生视频提示词）

审阅过程中同时修掉了**上一轮没发现、但直接决定视频观感**的一个 bug：

**旧实现**：视频 prompt 只取 panels.json 的 `prompt`（静态生图描述），把 `motion`（运镜）/ `action`（动作）/ `shot_size`（景别）三个视频专用字段**全丢了**，且锚点标签 `CHENMO_ANCHOR:` 原样传给视频模型（会画英文残字）。

**修复**（新增 `_build_video_prompt`）：
1. 消费 `motion` → 运镜指令（推/拉/摇/移/环绕，含 push-in/orbit 等别名归一化）
2. 消费 `action` → 「本镜头动作：XXX」
3. 消费 `shot_size` → 「镜头构图：XXX」
4. 剥离 `XXX_ANCHOR` 标签（机器路标，不进视频 prompt）
5. 保留锚点原文 + 反写实条款

实测输出（格 1，motion=zoom-in, shot_size=wide）：
> 「…（锚点原文）…；镜头构图：全景构图，主体完整入画；本镜头动作：陈默跨上电动车；镜头运动：镜头缓慢推近，聚焦主体」

## 五、建议的下一步（按优先级）

| 优先级 | 动作 | 解决哪一层 |
|--------|------|-----------|
| **P0** | 给 `_find_reference_art` 的内容匹配加**置信度阈值 + 跨角色混淆兜底**：匹配得分低于阈值、或多个角色得分接近时，宁可「不带参考图 + 如实告警」，也不传错人 | ② |
| **P0** | 分镜一致性校验从「打回」升级为「工具自动补锚点」：校验发现 prompt 未复用锚点且画面有人物时，由工具按 `action` 里的角色名确定性注入对应锚点，不依赖模型自觉 | ① |
| **P1** | 统一生图通道：把「参考图能力」设为硬约束，无参考图的格也不回退到 wan22（宁可用同通道纯文生图，保持能力对称） | provider 混用 |
| **P1** | 评估参考图遵循度：换 `image-01`（jdcloud，同样支持参考图）对比 qwen，或给定妆图补「多角度 + 多景别」版本，缩小参考图与分镜的差异 | ③ |

---

## 六、一句话总结

> **换脸的根本原因不是「视频模型不行」，而是「角色锚点」这条一致性主链，在『分镜 prompt 写标签』和『参考图定位』两个环节上各松了一环——前者模型不稳定、后者内容匹配会误判。两层叠加，让参考图要么传错人、要么没传，最终 83% 的格人物不一致。框架的约束层（校验硬闸、一致性抽检）都在正常工作并抓到了问题，缺的是「把这些约束变成确定性动作，而不是依赖模型自觉」。**
