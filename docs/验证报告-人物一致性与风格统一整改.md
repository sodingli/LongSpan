## 【新增】图生视频接入（2026-10-21 第二轮，FR-06）

### 问题

用户反馈：画面风格已保持一致，但成片仍是「一张图一张图」，没有真正连续动效。
诊断确认：图生视频能力（万相 wan3.0 `video.py::generate_clip`）**早已实现**，但只在
「画布手动模式」被调用；「一句话自动流水线」的动作链只有 `generate_images → synthesize_lines →
render_video`，**没有任何动作去调用图生视频**，故成片每格 `video=null`，全是静态图 + Ken Burns 运镜。

### 改动

| 文件 | 改动 |
|------|------|
| `app/harness/tools.py` | 新增 `generate_panel_videos` 工具 + `_keyframe_indices` 关键格选取 |
| `skills/comic-drama/manifest.yaml` | compose 阶段 `render_video` 前插入 `generate_panel_videos` 动作 |

关键格策略：**首格 + 中间格（n//2）+ 尾格** 确定性选取（不依赖模型自报），每格用首帧做
`first_frame`，时长 5 秒，走全局视频模型。结果写入 `media/images.json` 的 `video` 字段，
`render_video` 自然消费。失败如实降级为静态运镜（不卡死、不静默）。

### 验证结果（第 5 次真实跑，Run `4b7aa88d`）

- 关键格真实生成 3 段视频片段：`panel-0.mp4`（2.7MB）、`panel-6.mp4`（2.9MB）、`panel-11.mp4`（3.2MB）
- 成片 `final.mp4` 中格 0/6/11 的 `video` 字段非 null，各 5 秒真实动效，其余 9 格静态运镜
- 成片总时长 64.4s、1080×1920，全程 `attempt=1`（视频化没有引入额外重做）
- mock 冒烟（视频 off）正确降级为全静态，无回归

### 已知残留

- **P1** 图片文件用 1-based 枚举命名（panel-01.jpg）、视频片段用 index 字段命名（panel-0.mp4），
  在模型输出 0-based index 时两者命名有视觉错位（内部映射正确，但易误读）。
- **P2** 关键格只 3 段（成本折中）；若需全片连续动效，把 `_keyframe_indices` 改为全选即可，
  但成本会按 12×视频模型计。

## 〇、真实验证结论（2026-10-21 最终轮，4 次真实跑）

### 结论先行：人物一致性从「必然换脸」提升到「跨格同人」，验证通过 ✅

四次真实端到端任务（双主角故事，slow 精修通道，真实 LLM+生图+视频）：

| 轮次 | Run | 分镜 attempt | 结果与发现 |
|---|---|---|---|
| 1 | `83eeea95` | 4 | **发现 3 个真 bug**（参考图失联等），人脸仍漂（老匠格10 多白胡子） |
| 2 | `642b1f4e` | 4 | 发现第 4 个 bug（代码块语言标记污染指纹），全量误伤 |
| 3 | `94fda6e1` | 4 | 校验精准点名单格（真转述），人脸跨格一致 |
| 4 | `538227c1` | **1** ✅ | **修复收敛：全程 attempt=1、criteria_ok=True，参考图覆盖 12/12** |

### 真实跑暴露并修复的 4 个 bug（比单元测试值钱）

1. **锚点标签名与定妆图文件名对不上**：C4 提取锚点时角色名是中文（苏晚/林远舟），文件名只能落成
   `anchor_1.jpg`；C5 prompt 里是模型自造的拼音标签 `LINYUANZHOU_ANCHOR` → 参考图静默失联。
   修复：三级查找（标签文件名 → 锚点内容探针匹配 → 任意定妆图兜底）。
2. **探针被画风锚稀释**：锚点原文常被挤到 prompt 后半段，前缀相似度匹配落空。
   修复：改用「锚点前几个逗号子句」在 prompt 里做子串探针（≥20 字符命中即算）。
3. **代码块语言标记污染指纹**：模型写 ` ```text `，"text" 被抓进锚点指纹 → 指纹永远匹配不上 →
   全量误伤、空耗 3 轮重做。修复：正则剥离语言标记。
4. **纯物件特写被误判含角色**：格3 是怀表特写（"the stopped hands" 是钟表指针不是手），被要求带
   锚点 → 误伤。修复：正向人物特征词判定，无人物证据的格豁免。

### 真实跑的量化证据

- 锚点校验精准度：从「全量误伤 12 格」（轮 2）→「精准点名单格」（轮 3）→「一次通过 0 重做」（轮 4）。
- 参考图覆盖率：轮 3 为 10/12，**轮 4 达到 12/12 满分**（两位主角 anchor_1/anchor_2 交替出现，
  归属全部正确）。
- **人脸一致性（看图人工确认）**：老匠在格 2 与格 10 几乎同一张脸（皱纹分布、圆眼镜、深围裙
  全部对齐定妆图）；女主在格 1/格 5 同一人（黑长发、白衬衫、项链一致）。对比第 1 轮
  （未带参考图）格 10 老匠多出满脸白胡子、眼镜变形——参考图通道真实生效。
- 成本：每轮真实任务约 $0.04~0.09 / 14~20 分钟（轮 4 因 0 重做，降到 $0.045 / 14 分钟）。

### 已知残留（记录进后续版本）

- **P1** 风格统一仍靠文字画风锚：带 subject_reference 后 image-01 倾向写实电影感，
  与 prompt 声明的 "watercolor illustration style" 有偏差；跨格风格倒是一致的。
- **P2** 多角色同框格只带 1 张参考图（京东云协议限制）。
- **P2** 偶发生图失败会如实降级为 SVG 占位卡（符合「禁止静默降级」铁律），但该角色当轮
  无参考图；轮 4 未再触发，属低频偶发。

## 二、验证结果

### 1. 锚点提取（FR-01）✅

两种真实存在的锚点格式均正确提取：

| 格式 | 示例 | 提取结果 |
|------|------|----------|
| 冒号 | `CHENMO_ANCHOR: A 30-year-old...` | `CHENMO: A 30-year-old...` ✅ |
| 等号+引号 | `CHENMO_ANCHOR = "young Chinese man..."` | `CHENMO: young Chinese man...` ✅ |

角色名正确（去 `_ANCHOR` 后缀），锚点值干净无前缀残留。

### 2. 锚点复用硬校验（FR-02）✅

| 场景 | 结果 |
|------|------|
| prompt 逐字复用锚点原文 | **放行**（通过）✅ |
| prompt 转述/缩写锚点 | **拦截**（判失败，给出具体格号）✅ |
| 空镜/无角色格 | **豁免**（标注「无角色」）✅ |
| characters.md 缺失 | 判失败并说明「上游角色设计未完成」✅ |

**真实数据回归**：用真实任务 `fc03613749...` 的 panels.json（转述锚点）测试，正确拦截 11 格未复用锚点——**这正是原项目换脸问题的直接证据，硬校验精准命中**。

### 3. 定妆图产出（FR-03）✅

精修通道冒烟测试中，C4 角色设计阶段正确产出 3 个角色的定妆图：
```
characters/anchor_1.svg  (角色1定妆图)
characters/anchor_2.svg  (角色2定妆图)
characters/anchor_3.svg  (角色3定妆图)
```
（mock 模式下降级为 SVG 占位，真实生图服务下为 jpg）

### 4. 参考图通道（FR-04）✅

京东云生图请求体正确携带 `subject_reference`（官方协议结构，已查证文档）：
```json
{
  "model": "image-01",
  "prompt": "（已剥离 ANCHOR 标签的干净 prompt）",
  "subject_reference": [
    {"type": "character", "image_file": "data:image/jpeg;base64,..."}
  ]
}
```
- ✅ `_image_to_data_url` 正确转 base64 data URL
- ✅ prompt 未被 `XXX_ANCHOR:` 标签污染（已剥离）
- ✅ OpenAI 兼容 provider 不支持时如实标注「参考图未生效」（禁止静默降级）

### 5. 冒烟测试（fast/slow 双通道）✅

| 通道 | 结果 | 关键观察 |
|------|------|----------|
| fast（草稿） | ✅ 通过，1.87s，5 阶段全 completed | consistency_checks 的 slow_only 正确跳过（草稿不跑角色设计） |
| slow（精修） | ✅ 通过，7 阶段全 completed，含成片 mp4 | C4 定妆图产出 + C5 锚点校验真实触发 |

**修复前 vs 修复后**：C5 分镜绘制从 `attempt=4 criteria_ok=False`（锚点提取 bug 导致误伤）→ 修复后 `attempt=1 criteria_ok=True`（精确放行正确复用）。

## 三、结论

**三项核心整改全部落地并通过验证**：

1. **锚点硬校验**：把「逐字复用锚点」从提示词软约束升级为机器硬闸，精准拦截转述（换脸根因）。
2. **定妆图 + 参考图通道**：从根上解决换脸——C4 出定妆图，C5 逐格生图携带 `subject_reference` 做人脸一致。
3. **风格锚 + prompt 清洁**：剥离 `XXX_ANCHOR:` 标签污染，统一格式规范。
