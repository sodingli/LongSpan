## 一、背景与目标

### 背景

用户核心诉求是「一句话生成短视频故事，视频风格完整统一、人物保持一致、故事连贯无冲突」。

对当前 `comic-drama`（漫剧）技能的代码与真实产物（任务 `fc03613749c24a0f9d8dc49d2d94802d`）审查后，结论如下：

| 目标 | 现状 | 判定 |
|------|------|------|
| 故事连贯 | 已有 Logline 硬校验 + 剧本关卡 + 数据契约保护 | ✅ 基本达标 |
| 风格统一 | 仅靠「画风锚」文字提示词，无参考图 / 无全局 seed | ❌ 不达标 |
| 人物一致 | 锚点机制设计好，但**无机器校验、无参考图通道**，靠模型自觉 | ❌ 不达标（最严重） |

**根因（架构级）**：`generate_image` 只接收**文字 prompt**，没有任何「参考图」通道。C4 阶段设计的「定妆图 + 角色参考图」从未实现。纯文字描述 + 无 seed 锁定，跨格换脸是必然结果。实测抽样：主角陈铁在 02 格（45 岁欧美轮廓、左脸眉骨→颧骨疤痕）与 08 格（35 岁东亚面孔、额中疤痕）之间明显失守；道具 L-7 在 03 格（沙中金属盖圆罐）与 06 格（手持发光试管）之间漂移。

### 成功指标（可验收）

| 指标 | 口径 | 目标值 |
|------|------|--------|
| 锚点硬校验覆盖率 | 含角色的分镜格中，prompt 包含锚点原文的格数 ÷ 含角色格数 | 100%（机器强制，不依赖模型自觉） |
| 参考图使用率 | 有角色出现的格中，生图请求携带该角色参考图的格数 ÷ 有角色格数 | 100%（参考图通道可用时） |
| 人物一致性（主观抽检） | 同一角色在 ≥3 个景别不同的格中，脸型/发型/主色/标志配饰可辨识为同一人 | 达成（由多模态后检 + 人工抽检判定） |
| 风格统一性 | 相邻格色温/笔触/画风一致，无「明显跳戏」 | 达成（风格参考图 + 画风锚双保险） |

## 二、需求范围

### 包含（本期做）

1. **锚点复用机器硬校验**：C5 分镜阶段交出 `panels.json` 时，程序化校验每格 prompt 是否包含 `characters.md` 中对应角色锚点的原文子串；不含即判失败并自动重做（复用现有 `evaluate_criteria` 重做机制）。
2. **角色参考图通道**：C4 出定妆图；C5/C7 生图时携带角色参考图，从根上解决换脸。
3. **风格参考图 + 全局风格锚**：把画风描述固化为可复用锚，并支持风格参考图。

### 不包含（本期不做）

- 真人短剧 / 图生视频（当前技能定位就是动态漫，见 SKILL.md 铁律）。
- 多模态一致性后检自动化（P1，记入后续版本，本期仅作为人工抽检手段）。
- 道具类角色的独立参考图体系（P2，与人物参考图共用通道，先做人物）。

## 三、方案对比与选型

### 方案 A：锚点硬校验（先做，成本低收益高）

在 C5 阶段验收处新增「锚点包含校验」：读取 `characters.md` 提取锚点原文，逐格检查含角色的 `panels.json[*].prompt` 是否包含锚点子串。

- 成本：低（纯文本比对，无外部依赖）
- 收益：高（把「靠模型自觉」变成「机器强制」，直接堵住 paraphrase 漂移）

### 方案 B：角色参考图通道（治本，成本中）

扩展 `generate_image`，支持 OpenAI 兼容的 image edit 协议（或服务商参考图字段），把 C4 的定妆图作为参考图传入生图请求。

- 成本：中（需按服务商协议适配，但 video.py 已有 `_abs_ref` 转 base64 的先例可复用）
- 收益：最高（这是「换脸」的唯一根治手段）

### 方案 C：全局风格种子（辅助）

给「画风」设定确定性 seed 或风格参考图，保证风格不漂移。

- 成本：低
- 收益：中（风格问题严重度低于人物问题，但同样值得做）

**推荐**：A + B + C 三者组合，按 A → B → C 顺序落地。A 是「守住底线」的硬闸，B 是「治本」的手段，C 是风格侧的配套。三者互不冲突，共同构成「一致性三道防线」。

## 四、功能需求

### FR-01 锚点原文提取

- **描述**：从 `characters.md` 中提取每个角色的「一致性锚点」原文字符串。
- **规则**：识别 `characters.md` 中形如 `` `XXX_ANCHOR: ...` `` 的代码块或 `### 一致性锚点` 段落下的冻结字符串。
- **验收**：Given 一份含多个角色锚点的 characters.md，When 调用提取函数，Then 返回 `{角色标识: 锚点原文}` 的映射，锚点原文与文件逐字一致。

### FR-02 锚点包含硬校验

- **描述**：C5 阶段验收时，逐格校验 `panels.json` 中含角色的格，其 `prompt` 必须包含至少一个角色锚点原文子串。
- **规则**：
  - 从 `characters.md` 提取全部锚点；
  - 对每个 `panels.json[*]`，若 `prompt` 非空，检查是否包含任一锚点子串（或该格声明为「无角色格」）；
  - 含角色却未含锚点 → 判失败，触发自动重做（复用 `max_revisions_per_stage` 配额）。
- **验收**：Given 一格 prompt 未含锚点，When 校验，Then 返回失败并给出「第 N 格未复用锚点」的具体原因。

### FR-03 角色定妆图产出

- **描述**：C4 角色设计阶段产出每个角色的定妆图（参考图），落盘为 `characters/{角色}.png`（或 jpg）。
- **规则**：定妆图由真实生图服务产出，生图服务不可用时降级为程序化分镜卡并标注「占位」，不阻塞后续（但参考图通道随之降级为「仅锚点文字」）。
- **验收**：Given C4 完成，When 检查产物，Then 每个角色存在定妆图文件，且 `media/images.json` 或角色索引记录了定妆图路径。

### FR-04 生图参考图通道

- **描述**：`generate_image` 支持传入参考图（角色定妆图 / 风格参考图），随 prompt 一并提交生图。
- **规则**：
  - 参考图通过 `params` 或专用参数传入（`reference_image` 路径列表）；
  - 参考图读取后转 base64（复用 video.py 的 `_data_url` 模式）或直接传 URL，按服务商协议适配；
  - 服务商不支持参考图字段时，**如实标注「参考图未生效」**（禁止静默降级，架构铁律 #2），并降级为「锚点文字 only」。
- **验收**：Given 配置了支持参考图的服务，When 生图，Then 请求体包含参考图且产物人物与定妆图一致；Given 服务不支持，When 生图，Then 事件流如实说明「参考图未生效，仅锚点文字」。

### FR-05 风格锚固化

- **描述**：把「画风」从 `brief.style` 固化为统一英文画风锚，与角色锚点一样在每格 prompt 开头复用。
- **规则**：`production_spec` 阶段生成画风锚字符串，写入 `spec.json`；C5 每格 prompt 以「画风锚 + 角色锚点」开头。
- **验收**：Given 一份 spec.json，When 检查，Then 含 `style_anchor` 字段且非空；Given panels.json，When 检查，Then 每格 prompt 以画风锚开头。

## 五、业务流程与状态流转

**整改后的 C4→C5→C7 生图链路：**

```
C4 角色设计（关卡）
  └─ 产出 characters.md（锚点原文）+ characters/{角色}.png（定妆图）
        │
        ▼
C5 分镜绘制
  ├─ 模型产出 panels.json（每格 prompt = 画风锚 + 角色锚点 + 动作场景）
  ├─ 【FR-02】锚点硬校验：不含锚点的格 → 判失败 → 自动重做
  └─ 【FR-04】generate_images：每格生图携带对应角色定妆图
        │
        ▼
C7 合成
  └─ 补齐缺失分镜图（幂等，同样携带参考图）→ render_video
```

**状态机无新增状态**，复用现有 `StepStatus`（IN_PROGRESS / PENDING / COMPLETED / FAILED）与 `max_revisions_per_stage` 配额。锚点校验失败表现为「验收未通过，自动重做」，与现有文本类验收失败路径一致。

## 六、非功能需求

- **性能**：锚点硬校验是纯文本比对，单次 < 100ms，不影响 TTFV 指标。
- **兼容**：参考图通道是增量能力，服务商不支持时优雅降级，不破坏现有 OpenAI 兼容生图路径。
- **诚实性**：参考图未生效、定妆图占位、锚点校验失败等，一律在事件流与产物中如实标注（架构铁律 #2）。

---

## 七、异常处理清单

| 场景 | 处理 |
|------|------|
| characters.md 未产出锚点 | C5 校验报「缺角色锚点」，判失败重做（上游未完成） |
| 角色定妆图占位（无真实生图服务） | 参考图通道降级为「仅锚点文字」，事件流如实说明 |
| 服务商不支持参考图字段 | 请求体不含参考图，产物标注「参考图未生效」，事件流说明 |
| 某格 prompt 未含锚点 | FR-02 判失败，自动重做该阶段 |
| 锚点包含校验误伤（prompt 超长被截断） | 校验用「子串包含」而非「完全相等」，规避格式差异 |
