# Longspan · 八周路线图（2026-10-22 → 2026-12-18）

> 依据：`MRD-Longspan.md` §0（定位：价值不在生成，在约束与留痕）、§0.6（三条判定线）
> 执行依据：`PRD-演出约束与一致性分层.md`
> 周期：8 周，每两周一个**可演示增量**（不是"功能列表"，是"能给人看的东西"）

---

## 零、这份路线图的立场

1. **每周交付一个能演示的增量**，而不是"做完再给你看"。演示可以是：一集成片、一个自检报告、一个数值。
2. **每周记录三个数**（MRD §0.6）：返工率、场景数/结构违约数、TTFV 里"等人"占比。数不改善的周，下周不许加新功能。
3. **不追模型**。八周里模型会换 2–3 次（供应商、版本），路线图假设"模型能力不变"来做规划，这样才不会被平台更新打乱。
4. **能力层只做接入**。任何"等某个模型支持 XX"的需求，一律降级为"记录在案，等它出现再接线"。

---

## 一、八周后产品应该"能做什么"（能力台账）

到第 8 周结束时，以下五条必须为真，否则这八周只是做了个更漂亮的 demo：

| # | 能力 | 可验收的判据 |
| --- | --- | --- |
| C1 | **一集 12 格的结构违约 = 0** | 自检脚本 PASS；返工率 ≤1/12 |
| C2 | **场景不漂移** | 同场景跨格背景元素可辨识为同一空间（人工抽检 3 例） |
| C3 | **一致性可诊断** | 任何一集能回答"哪一格可能换了脸、依据是什么"，并给出重绘入口 |
| C4 | **换题材 0 行代码** | 新开一集只改 manifest；`git diff` 里无 `backend/app/**` |
| C5 | **流程可迁移** | 第二个技能复用同一套 `directing` / `consistency_checks` / 关卡机制 |

## 二、四段节奏

### 第 1–2 周：让约束真正咬合（约束层 L3）

| 周 | 交付 | 演示 |
| --- | --- | --- |
| W1 | `directing` 解析 + `shot_budget` / `scene_reference` 校验器 + 场景卡注入 + 自检脚本 | 用旧任务反跑自检，当场指出"格 3/4 撞景别、缺场景卡" |
| W1 | **硬约束违约 = 阶段失败**（不再带病完成） | 故意交一份违规 panels.json，看它被判失败而不是"完成" |
| W2 | 提示词侧的"先排表"规范 + 12 格景别节奏表 | 同一题材跑一集，结构违约从 3 条降到 0 |
| W2 | 指标落库：返工率、场景数、TTFV 分段（机器/等人） | 打开一集，直接看到三个数 |

**W2 的出口判据**：连续两集 C1 成立（自检 PASS，返工 ≤1/12）。不成立就继续打磨，不进入下一段。

### 第 3–4 周：补素材层（约束层 L2）

| 周 | 交付 | 演示 |
| --- | --- | --- |
| W3 | 生图 provider 能力矩阵（`supports_reference` / `negative` / `seed`）+ 按格选路 | 含角色的格自动走参考图通道，事件流写明"为什么这一格换了通道" |
| W3 | 画布重绘透传参考图 | 手改一格，脸不再变 |
| W4 | 一致性抽检（只告警）：人脸区域直方图 + SSIM 与定妆图比对 | 一集跑完给出"格 7 相似度 0.42，建议重绘" |

**W4 的出口判据**：C2 成立（人工抽检 3 例），且抽检误报率可接受（<30%）。

### 第 5–6 周：证明可迁移（资产层）

| 周 | 交付 | 演示 |
| --- | --- | --- |
| W5 | `ppt-deck` 也声明一份 `directing`（页数预算、每页一个论点、版式节奏）+ 一个校验器 | 一份 20 页 PPT 因为"连续 4 页都是要点列表"被判失败重做 |
| W6 | 把"结构约束 + 校验器 + 自检脚本"抽成通用能力（不再是 comic-drama 专属） | 两个技能共用同一套机制，代码里没有技能名 |

**W6 的出口判据**：C4 + C5 成立。

> 这一步是**整个项目的分水岭**。如果做不到"第二个技能复用同一套机制"，说明这套东西还是"漫剧专用脚本"，那它的定位就从 B（编排内核）掉回 A（出片工具），要重新评估还值不值得做。

### 第 7–8 周：交付形态与稳定性

| 周 | 交付 | 演示 |
| --- | --- | --- |
| W7 | 半自动交付：批量出素材 + 分段人审 + 一键导出（承认"最后剪辑交给人"） | 30 分钟内产出 3 集可用素材包 |
| W7 | 失败恢复：硬约束失败后的"从哪继续"引导（不是只报错） | 故意断网，恢复后续跑到原处 |
| W8 | 成本与时长账本：每集实际耗时/花费 vs 预算 | 一页看板，把"自动化到底省了什么"说清楚 |

**W8 的出口判据**：三条判定线全绿，且能用一页数据回答"这套东西比手工快多少、稳多少"。

## 三、贯穿八周的纪律（比功能更重要）

1. **每次改约束，先问"能不能机器校验"**。不能校验的规则不进提示词（MRD §7.4 原则 4）。
2. **每个新校验器必须配一个正样本**。只会说"不通过"的校验器会逼模型乱改，比没有更糟。
3. **失败要带格号**。"不合格"三个字不产生任何改进；"格 4 的 action 含两个动作"能直接改。
4. **不为了过校验而放松校验**。模型过不了，先改提示词与结构（prescribe），最后才调阈值；调阈值必须写进 manifest 并留痕。
5. **每周留一次"人看片"**。指标能证明结构，证明不了好看。

## 四、停止条件（写在这里，免得沉没成本替我们做决定）

出现以下任一情况，停下来复盘定位，而不是继续加功能：

- W2 出口判据连续两周不达标（结构违约压不下去）→ 说明"约束"这条路在漫剧上收益有限，回退到 C（半自动辅助）；
- W6 出口判据不达标（第二技能复用不了）→ 说明它是个专用脚本，不是内核，重新决定要不要继续投入；
- 单集成本持续高于"人工外包"的等价成本，且返工率没降 → 经济性不成立。

## 六、W4 待决（2026-10-23 实测后）

分镜一次通过率 0/4，两条文案级修法无效。往下有三个方向，按"能不能机器保证"排序：

| 方向 | 做法 | 预期收益 | 代价 | 与产品定位的关系 |
| --- | --- | --- | --- | --- |
| A. 骨架真正前置（推荐先做） | `scene_id` / `shot_size` / `motion` / 格数由代码注入并回填，模型只填 `action` / `prompt` / `subtitle` / `speaker`；偏离即机器纠正 + 事件留痕 | 直接消灭「换场 ABA」「景别节奏」「清单形状」这类结构违约（占违约的 1/3～1/2），且不再靠模型自觉 | 半天；要改 runner 一处注入 + 一个回填函数 + 自测正样本 | 正中「约束层重投入」——结构是能机器保证的，就不该写成提示词约定 |
| B. 换更强文本模型跑分镜（诊断性） | 只对 storyboard 阶段换 `Qwen3.8-27b` / `MiniMax-M3`，跑 1 集对比 | 若一次通过，说明瓶颈是模型对否定式约束的服从度 | 单集成本上升；按 §7.4 属"换模型能解决"，价值排序应靠后 | 这是一次**诊断**，不是长期方案：结论要落回 A 或 C |
| C. 接受 C1 不达标，回退 C 路线 | 按本文第二节的出口判据，W2 未过即回退"半自动辅助" | 不再为一个 0/4 的指标烧时间 | 放弃全自动成片定位 | 需要先确认：0/4 是"约束太严"还是"模型太弱"——A 做完才有资格下这个结论 |

不建议的：放宽判据（如允许 1 轮重做）。那是把测量改成迎合结果的数字，不是把流程改好。

## 七、W4 方向 A 已落地（2026-10-23 02:00）

**做了什么**：把「结构」从提示词约定改成机器保证。
- 新增 `backend/app/harness/skeleton.py`：按 `spec.json` 的 `grid_count` 生成骨架
  （格数 / 每格 scene_id / 每格 shot_size / 剧情功能，功能取自 `rhythm_table`）；
  相邻景别有确定性的收尾修正（骨架自己不许撞车）。
- `manifest.yaml` 的分镜阶段声明 `skeleton: {kind: panel_grid, spec: spec.json, target: panels.json}`
  —— 数据驱动，runner 里没有"漫剧"字样。
- 两处 runner 钩子：① 提示词末尾渲染**按真实格数生成**的骨架表；② 模型交卷后、
  动作执行前**回填** scene_id / shot_size 并逐条写 decision（模型原值保留在 `_declared_*`）。
- `prompts/05_storyboard.md` 里那张写死的 12 格表已删除（它和真实格数打架，是换场违约的源头）。
- 自测：`scripts/selftest_skeleton.py` 32 条（含每条规则的反样本、幂等、超纲格/缺格）；
  另补 `scripts/selftest_names.py`（自建未定义名检查，51 文件通过，注入错误可抓）。

**效果（run 056b9b08，12 格）**：

| 指标 | 改造前（04/05/06/07） | 改造后（09） |
| --- | --- | --- |
| 分镜尝试次数 | 3 / 3 / 4 / 3 | **2** |
| 返工率 | 0.125~0.250 | **0.083（达线 ≤1/12）** |
| 结构类违约（换场/景别） | 每集都有 | **0** |
| 机器回填留痕 | — | 14 处（模型自写的 S2/S1 错位被改回，逐条记录） |
| 剩余违约 | — | 首轮 2 条「多动作（然后）」，第二轮自愈 |

**结论**：结构类违约被消灭，这是"能机器保证的不要写成提示词"的直接验证。
剩下的唯一违约族是 `action` 里写两个动作 —— 它属于内容字段，是否也纳入机器回填是个
产品边界决定（见下）。

**待定**：`action` 是否也机器处理（把"然后"之后的部分保留为 `action_beat2` 并留痕，
`action` 只留一段）。好处：首轮违约归零，C1 判据可达；代价：panels.json 与
storyboard.md 两份文本不再逐字一致，需要一并改写 storyboard.md 或明确它只是人读版。

## 八、产品化 P0-1：角色资产库（2026-10-23）

### 为什么做这个（产品判断，不是技术判断）

盘了现状之后暴露一个事实：**产品是「流水线调试台」，不是「生产工具」**。
证据三条：

1. 8 个 run 目录里散落 `anchor_1.png` / `chenmo.png` / `l7.png`，角色**按 run 隔离**。
   第二集想用第一集的主角，只能重新生图、重新赌一次一致性。
2. `/runs/{id}/download` 把整个工作区打成 zip（781 条 artifact），运营拿到是 json+png 混合物。
3. `metrics.json` / `audit_*` 只对开发者可见，用户在界面上看不到「这条能不能发」。

漫剧是**系列**产品，系列的资产是角色。这件事不做，「出第 2 集」永远是重新开始。

### 做了什么

| 层 | 内容 |
| --- | --- |
| 数据 | 新表 `characters`（name / slug / anchor / card / art / 出处 / 复用次数）+ `character_usages`（出场记录） |
| 资产 | 定妆图复制到 `.data/characters/<slug>.<ext>`，**独立于 run 生命周期**（删任务不删资产） |
| 注册 | `characters` 阶段产出后自动入库（run 结束时执行，失败/取消也登记）；另有 `POST /api/characters/scan` 导入存量 |
| 复用 | 开跑前把角色的图 + 角色卡物化进目标 run 的 `characters/` 与 `characters.md` |
| 回填 | `characters.md` 被模型整份重写时，锁定角色卡强制改回库版，偏离写 decision |
| 提示词 | 角色阶段给「已锁定，禁止改写」；**分镜阶段给锚点原文，要求每格逐字复用** |
| 界面 | 侧边栏「角色库」资产页（改名 / 换定妆图 / 删除 / 出处与出场集数）；创建面板「沿用已有角色」多选 |

### 关键设计取舍

- **物化而不是改链路**：复用不改 `_find_reference_art` 的四级查找，只把文件放到它原本就在找的位置。
  复用的定妆图是**同一个文件**，一致性是确定的，不是「概率上接近」。同时零回归风险。
- **解析按锚点归属，不按标题层级**：`characters.md` 是模型自由书写的，实测同一份里
  `## 角色卡` / `### 老渔民` / `#### 一致性锚点` 三层混用。按层级判定会把子节当角色、
  把容器当角色卡（这两种都真实发生过）。现规则：子节标题排除 → 块内 ≥2 个锚点判容器 →
  恰好 1 个且未被更深的块认领才算角色。
- **同名不覆盖**：后来的集若同名角色，只记出场，不覆盖锚点与定妆图（覆盖等于悄悄改人设）。
  要换图走 PATCH（用户显式操作，留 `anchor_history`）。
- **fast 通道也要能吃**：fast 没有 `characters` 阶段，所以分镜阶段注入锚点原文 ——
  否则模型自创锚点，库里的定妆图永远匹配不上。

### 自测

`backend/scripts/selftest_characters.py` 19 条：解析正样本 + 三类反样本（子节标题 / 容器 / 非人物锚点）、
slug 稳定性、物化幂等、`_index.json` 留痕、**下游 `_find_reference_art` 能吃到复用图**、
模型改写后被回填且留痕。

### 遗留

- 角色目前是**工作台级**（按名字唯一），不同题材出现同名角色会合并。真正的解是「系列/项目」维度，
  等「系列模式」一起做。
- 复用只覆盖定妆图与角色卡；场景锚（同一场景的空间连续性）还没有资产化。
